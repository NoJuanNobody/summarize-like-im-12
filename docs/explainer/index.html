What is summarize-like-im-12 and what is it like to use?

Long image

A

Answer

It is an Agent Skill: one instruction file for your AI coding agent. It makes the agent explain code, papers, agent logs and diffs as if to a sharp 12-year-old, with analogies and real file links.

  1. You add it to your agent with one command, then ask in plain words, such as “summarize like im 12” or /eli12.1
  2. The agent reads SKILL.md and follows its five rules: analogy first, every term translated, 3 to 5 numbered beats, real links, no talking down.2
  3. There is no program to run. The repository holds only README.md, SKILL.md and setup.py; your agent does the writing.

What happens when you use it?

Diagram structure
  • You you
  • Your AI agent agent
  • SKILL.md rules skill
  • Your file, diff or paper input
  • you → agent · npx skills add … -g (once)
  • you → agent · “summarize like im 12” + what to explain
  • agent → skill · load the matching skill
  • agent → input · read the material
  • agent → you · analogy hook + 3–5 numbered beats + links
  1. Install once ↗

    Run npx skills add NoJuanNobody/summarize-like-im-12 -g to add the skill to your agent.

  2. Ask in plain words ↗

    Say “summarize like im 12”, “explain like im 12”, /eli12 or “break this down simply”, and point at what to explain.

  3. Agent loads the rules ↗

    The agent matches your phrase to the skill and reads SKILL.md.

  4. Agent reads your material ↗

    A codebase, an agent build log, a research paper or a git diff.

  5. You get the explanation ↗

    It starts with “Imagine…”, translates each term in brackets, and links every part to its real file or URL.

What goes in, and what comes out?

PartWhat it is
Goes inA codebase or architecture, a multi-agent build log, a research paper, or a git diff.3
Opening lineOne sentence that compares the system to something everyday, such as a vending machine or a LEGO line.
Every termTranslated on first use, for example Git worktree → “each robot builder gets its own desk”.
Body3 to 5 numbered beats with catchy titles, each with a link to the real file.
EndingOne or two sentences on how the parts hand off to each other.4
